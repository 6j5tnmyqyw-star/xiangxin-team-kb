## 0. 总览（先看这块再开干）

### 0.1 装完之后你能干啥

- 用**飞书机器人（lark-cli）**让 AI 读/改飞书文档、查 Base、列日历、发消息（用你的飞书身份）——**这是全员必配**
- 知识库（Obsidian vault / 飞书文档）里的内容长期保留——换 AI 软件也不丢
- 已有任意 AI 客户端（含已装好的豆包）时，把工作目录指到知识库，即可本地读写笔记
- 需要时让 AI 打开浏览器帮你跑公司系统（吉客云、抖店、京麦、千牛等）——按岗位与当前客户端能力，见 §4

### 0.2 架构原则（为什么要配飞书机器人）

| 层 | 是什么 | 换工具时 |
|-|-|-|
| **内容层** | Obsidian 知识库、飞书文档 / Base / 任务 | **保留** |
| **集成层** | 飞书机器人（lark-cli 登录、权限、习惯用法） | **保留** |
| **客户端层** | 你当前用的 AI 软件（可选；不强制全员装豆包电脑版） | **只换这一层** |

> 🌟 一句话：**内容在飞书/知识库里，机器人是桥；客户端可换、可暂无。** 以后切换智能工具，直接换软件就行，内容还在。

### 0.3 整套要装 / 要配的东西

| 组件 | 作用 | 难度 | 必装 |
|-|-|-|-|
| **飞书机器人（lark-cli）** | 让 AI 操作飞书文档 / Base / IM | ⭐⭐ | ✅ **必配** |

## 1. 关于豆包客户端（不强制下载）

> 🌟 **阿祥最新口径：不用大家下载豆包电脑版了。**  
> 本手册主路径是 **§2 飞书机器人 + §3 知识库**。豆包桌面端 / 电脑操控**不是**全员必装项。

### 1.1 怎么理解

- **必做**：配好飞书机器人（lark-cli）、搭好知识库（推荐 Obsidian）
- **可选**：你电脑上**已经有**豆包或其它 AI 客户端 → 继续用即可，把工作目录指到 vault（见 §3.5）
- **不要做**：为了跟本手册「对齐」再去官网 / 应用商店专门下载一套豆包电脑版

### 1.2 和「飞书机器人」怎么配合

- **lark-cli（飞书机器人）**：以你的飞书身份读写飞书文档 / Base / IM —— 全员底座
- **本机 AI 客户端（若有）**：对话、改本地文件、按客户端能力操控界面
- 日常可以说：「用飞书机器人把 XX 文档 §3 改成 YY」——AI 应走 lark-cli，而不是让你手拷内容

### 1.3 以前写过的「装豆包电脑版」步骤

> 已作废。不再提供下载链接、开通清单或「待补装机步骤」。有疑问直接问阿祥，不要自行下载安装。

## 2. 配置飞书机器人（lark-cli）⭐ 必做

> 这是**耐久集成层**。换客户端（或暂时没有桌面 AI）时，飞书这边尽量少动。阿祥强调：**要大家配置好机器人。**

### 2.0 前置：装 Node.js

#### Mac

打开终端，按需装 Homebrew 后：

```Bash
brew install node
node --version
```

输出 `v20.x.x`（或更新 LTS）即可。

#### Win

打开 [https://nodejs.org/zh-cn/download](https://nodejs.org/zh-cn/download) → 下 LTS 的 Windows Installer → 下一步装完。  
命令提示符里：

```Plain
node --version
```

> 报「不是内部或外部命令」→ 重启电脑再试；还不行找阿祥。

### 2.1 装 lark-cli

```Bash
npm install -g @larksuiteoapi/lark-cli
```

Win 若报权限不足：用**管理员**重开 cmd 再装。  
`npm` 卡死可切国内源：

```Bash
npm config set registry https://registry.npmmirror.com
```

### 2.2 登录公司飞书账号

```Bash
lark-cli auth login
```

浏览器打开授权链接，**用你公司飞书账号**扫码授权。  
第一次可能要阿祥在飞书后台批 scope——先跟他说一声。

### 2.3 验证

```Bash
lark-cli im chat list
```

能列出你的飞书群 = 成功。

也可：

```Bash
lark-cli auth whoami --as user
```

### 2.4 告诉 AI：本机已装飞书机器人

在你的知识库根规则文件（见 §3）里加一段，例如：

```Markdown
## 飞书操作
本机已经装好 lark-cli，登录的是我（XX）的公司飞书账号。
需要操作飞书文档 / Base / IM / 日历时，直接用 lark-cli 命令（优先 --as user）。
不会的命令现学：lark-cli --help 或 lark-cli <子命令> --help。
外发消息、群发、@ 别人、改别人文档：先给我看草稿，我确认后再执行。
```

### 2.5 和「专属飞书私聊机器人」的关系（可选了解）

公司另有「XX AI」这类飞书私聊机器人方案（同事专属 bot）。那是**另一条通道**（飞书里私聊机器人）。  
**本手册要求每人先把本机 `lark-cli` 配通**——这是通用底座。专属 bot 是否给你开、怎么开，听阿祥安排，不在此展开。

## 3. 知识库（Obsidian）——内容层，换工具也不丢

> 对应标准五步的 **第 2–5 步**：装 Obsidian → 指工作目录 → 写规则 → 灌入公司共享内容。

> 可选但**强烈推荐**。知识库是「内容还在」的本地落点；飞书是云端落点。两边都在，换客户端不伤内容。

### 3.1 装 Obsidian（命令行 / GitHub，不要去官网点下载）

> ⚠️ **不要去**[https://obsidian.md](https://obsidian.md) 官网点下载。统一从 GitHub 发布页或下面命令行安装：  
> 发布页：https://github.com/obsidianmd/obsidian-releases/releases  
> （里面有 AppImage / dmg / exe 等；版本号以发布页最新为准，下文示例为当前最新 `1.14.4`。）

装完后：设置（左下齿轮）→ Language →「简体中文」。

#### Mac（推荐 Homebrew cask）

```Bash
brew install --cask obsidian
```

或命令行从 GitHub 拉最新 `.dmg`（示例；文件名随版本变，先看 releases）：

```Bash
cd ~/Downloads
curl -L -o Obsidian.dmg "https://github.com/obsidianmd/obsidian-releases/releases/latest/download/Obsidian-1.14.4.dmg"
# 若 latest/download 文件名对不上，先查资产名：
# curl -sL https://api.github.com/repos/obsidianmd/obsidian-releases/releases/latest | grep browser_download_url | grep -i '\.dmg'
hdiutil attach Obsidian.dmg
cp -R "/Volumes/Obsidian/Obsidian.app" /Applications/
hdiutil detach "/Volumes/Obsidian"
```

#### Windows（命令行，不走官网页面）

PowerShell / 终端：

```PowerShell
# 推荐 winget
winget install --id Obsidian.Obsidian -e

# 或 scoop
scoop bucket add extras
scoop install obsidian

# 或直接从 GitHub 下安装包（版本号按 releases 最新改）
# Invoke-WebRequest -Uri "https://github.com/obsidianmd/obsidian-releases/releases/latest/download/Obsidian-1.14.4.exe" -OutFile ObsidianSetup.exe
# .\ObsidianSetup.exe
```

#### Linux（AppImage，curl 拉最新）

```Bash
mkdir -p ~/Applications && cd ~/Applications
curl -sL https://api.github.com/repos/obsidianmd/obsidian-releases/releases/latest \
  | grep -oE 'https://[^"]+Obsidian-[^"]+\.AppImage' | head -1 | xargs -I{} curl -L -o Obsidian.AppImage {}
chmod +x Obsidian.AppImage
./Obsidian.AppImage --no-sandbox
```

> x86_64 一般选不带 `arm64` 的 `Obsidian-*.AppImage`；ARM 机器选 `*-arm64.AppImage`。

### 3.2 新建你自己的 vault

建议命名：`<你名字>AI`（如 `庆弘AI`、`荔枝AI`）。  
Mac 可放 iCloud；Win 可放 OneDrive——方便手机端同库查看。

### 3.3 建议目录（简化版）

```Plain
_待整理/        Inbox：AI 新写文件默认放这里
00-入口/        知识地图
01-每日/        日记 / 复盘
02-人物/        可选
03-工作/        会议 / 项目 / SOP
04-内容创作/    视频 / 文案（按岗）
05-知识/        长期知识
07-AI协作/      规则与模板
99-附件/        图片 / 截图
```

### 3.4 根规则文件

vault 根目录放一份「我是谁 / 铁律 / 飞书已登录」说明（旧手册叫 `CLAUDE.md`；现在可用同内容改名，或按你当前客户端要求命名）。  
**重点**：写清姓名、岗位、文件落盘规则、§2.4 的飞书段、§5 安全红线。

### 3.5 让 AI 客户端指向你的 vault（若本机有客户端）

若你**已有**任意 AI 客户端（含已装好的豆包，或其它工具）：把工作目录 / 项目目录选成**你的 vault 根目录**，不要选 Desktop / 整个用户目录。  
选错了 AI 找不到规则文件，也会把文件写乱。  
**没有桌面 AI 客户端也不影响**：飞书机器人 + Obsidian 笔记仍可按本手册使用。

## 5. 安全规则（⚠️ 必读 · 外发需确认）

1. **客户隐私不进 AI**：顾客姓名、手机、地址、身份证、订单号、旺旺等，不要粘贴到对话框
2. **公司内部财务 / 成本**：可以跟 AI 聊协助分析（阿祥已定口径）；**HR**（工资、绩效、人事矛盾）不进 AI
3. **外发需确认**：飞书群发、@ 别人、对外邮件 / 客户消息、改别人文档、批量删除——**AI 先出草稿 / 方案，你点头再执行**
4. **lark-cli 用的是你的飞书身份**：发出去署你的名；不确定就先 `whoami` / 先看草稿
5. **大动作先方案**：批量改飞书、动库存数字、动定价——先方案后执行
6. **账号与密钥**：飞书授权、机器人 Secret、本机登录态不进群、不截图外传

## 7. 翻车了怎么办

| 情况 | 解决 |
|-|-|
| `lark-cli` 找不到命令 | 重装：`npm install -g @larksuiteoapi/lark-cli`（Win 管理员） |

| AI 改坏了本地文件 | Obsidian「文件恢复」/ iCloud·OneDrive 版本历史 |
| AI 要群发 / 外发 | **先停**——必须你确认（§5） |
| 装完设置不生效 | 相关软件只关了窗口还在托盘跑 → **彻底退出再开** |
| 有人让你去下豆包电脑版 | 以本手册为准：**不必下**；有疑问问阿祥 |

## 10. 以后换智能工具时怎么做
