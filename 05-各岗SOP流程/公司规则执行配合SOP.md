# 祥新公司规则执行配合 SOP

> 发布人：邹祥书｜生效日期：2026-05-13｜版本：v1.0
> 面向对象：祥子AI / Claude Code / 小龙虾 等 AI 协作者；同步精炼版给团队成员
> 维护：本文件是知识库主版本，飞书文档是团队可见副本，本地变动以本文件为准

---

## 一、适用范围

AI 在祥新公司知识库工作时，遵循本 SOP 完成三件事：

1. **读懂公司**：在动手前先了解公司业务、店铺、团队、当前阶段
2. **同步文档**：在知识库与飞书之间保持文档一致，团队拿到的是同一份
3. **管理任务**：把祥书（老板）口头/对话中布置的事项，落成飞书任务并指派到人

本 SOP 不展开各业务线细节，业务线 SOP 见第三节清单。

AI 接到任意任务前先建立这层底层认知：

| 模式 | 高尔夫用品撮合分销，自有库存 30-40% + 第三方代发 50-60% |
| 主营 | Bushnell 测距仪、Garmin 高尔夫手表/GPS、Ping & Callaway 球杆周边 |
| 团队 | 5 名运营专员 + 祥书 + 妻子（设计/财务/竞品）+ 仓储/行政 |
| 当前阶段 | 618 备战 / 倍视能库存清仓 / 自有品牌探索 |
| 战略重点 | SOP 标准化提效（不扩人）→ AI 挖需求做自有品牌 |

> 详细背景：[[03-公司/00-公司全景]]｜团队人员清单：见飞书 Base「📈祥新日常工作总表」

### 业务铁律（违反必须主动提醒）

1. 比价以**天猫**为基准，不用京东价
2. 618 期间不随意改主图，改前必须告知祥书
3. 任何对外文案禁止违禁词（详见 [[07-AI协作/规则/03-内容创作规范]]）
4. 客户隐私（姓名/手机号/地址/订单号）禁止出现在任何 AI 输入/输出
5. 店铺后台截图、订单数据不外传
6. AppID / AppSecret / 密钥不写进代码，统一走环境变量

## 四、文档双向同步流程

### 4.1 权威源约定

| 内容类型 | 权威源 | 说明 |
|---|---|---|
| AI 工作规则 / 内部 SOP | **本地知识库** | 飞书是只读副本 |
| 团队对外正式规则 / 流程 | **飞书** | 知识库存归档备份 |
| 团队任务 / 派工 | **飞书任务** | 看板 [[03-公司/待办与跟进/团队任务看板]] 是祥书视角 |
| 公司问题日志 | **飞书 Base「Claude纠错日志」** | 知识库不重复记录 |
| 会议纪要 | **飞书妙记** | 知识库存提炼版 |

### 4.2 知识库 → 飞书（正向同步）

触发：任何**团队需要看到**的规则、SOP、培训文档完成或重大更新后。

AI 操作：

1. **确认是「团队可见」内容**：仅个人笔记、AI 内部规则、未定稿的草稿不同步
2. **挑选目标位置**：默认创建在 `飞书云空间 / 公司 SOP /` 下，若祥书已指定知识库节点则用指定位置
3. **用 [[lark-doc]] skill 创建**：从 Markdown 直接创建飞书文档
4. **回复祥书**：给出飞书文档链接 + 一句话总结
5. **本地文件 frontmatter 加链接**：在文档首部加 `飞书文档：<url>` 一行，便于反查
6. **如祥书需要推送到群**：明确说"要推到 XX 群吗？"再动，AI 不擅自推送

### 4.3 飞书 → 知识库（反向同步）

触发：祥书或同事在飞书里产生了内容（妙记 / 多维表格 / 文档），希望沉淀到知识库。

AI 操作：

1. 用对应 skill 拉取（[[lark-minutes]] / [[lark-doc]] / [[lark-base]]）
2. 落 [[07-AI协作/规则/09-知识库写入规则]] 的命名规则
3. **首次写入默认进 `_待整理/`**（Inbox-first，见 [[10-待整理工作流]]），由祥书或归档进程移到正式位置
4. 例外：祥书明确指定目标位置 / 在已存在文件上追加 / 走特化 SOP 的最终成品（如本 SOP）→ 可直接写正式目录

### 4.4 冲突解决

同一份内容飞书与知识库都有，且不一致时：

- **规则 / SOP 类**：以本地知识库为准，AI 用 [[lark-doc]] 覆盖飞书副本
- **任务 / 状态类**：以飞书为准，AI 拉取后更新本地看板
- **重大冲突**：先停止同步，回报祥书决策

## 五、领导指令 → 飞书任务（核心新增）

### 5.1 定义

「领导指令」= 祥书在对话、录音、群聊、日报评论里**明确布置给某人**的事项。
判定关键词：「让 X 做 Y」、「X 去把 Y 搞一下」、「明天之前 X 给我 Y」、「@X 你负责 Y」。

> 模糊场景：祥书只是发议论 / 思考 / 抱怨，没指人没指事 → 不建任务，按 [[11-问题记录与处理流程]] 落到纠错日志候选。

### 5.2 自动建任务条件（4 选 1 即触发）

1. 祥书直接说「给 X 派个任务」、「让 X 去做 …」
2. 祥书在录音/对话中明确点名分工，并给出可执行动作
3. 群聊汇总抽出的、祥书亲自布置的待办
4. 日报评论中祥书要求改进的具体动作

> ⚠️ 不在触发列表内：祥书自言自语的「我应该去做…」、未指人的「下次注意」、纯吐槽。

### 5.3 写入飞书任务的默认参数

| 字段 | 默认值 | 说明 |
|---|---|---|
| 标题 | 动词开头 + 具体对象（10-20 字） | 例：「下架天猫倍视能 V6S 库存预警 SKU」 |
| 描述 | 背景 1 句 + 验收标准 1 句 | 不超过 5 行 |
| 负责人 | 祥书指名的人（用 [[lark-contact]] 解析 open_id） | 不要群挂 |
| 关注人 | 祥书自己（默认） | 让他能看到进度 |
| 截止时间 | 当天 18:00（若是上午布置）/ 次日 18:00（若是下午布置）/ 祥书指定优先 | 没说不设也可以，但要在回执里问一句 |
| 清单 | **默认挂【祥新任务】**（guid `a1b4297b-0a7a-4b0e-8748-e0b75ae15485`） | 全公司任务统一在这个清单里，团队成员靠它找活儿。⚠️ 不要选成【祥新任务（祥书账号）】(`a543155a-...`) |
| 标签 | 业务线（电商运营 / 售后 / 内容 / 财务 等） | 选填 |

> 关于批量场景：原 `lark-xiangxin-yunying-task` skill 用于"祥书一次性把同一件事派给运营组 5 人"的场景（如调价/上下架/拍摄/整理），自带会签 + 自动挂清单，那种走旧 skill。本 SOP 处理的是**单点派任务**——同样默认挂【祥新任务】，但负责人只有一个。

### 5.4 AI 操作流程

**Step 1：识别意图**

听到/读到指令后，先复述给祥书确认一句：

```
我理解的：让 <X> 做 <Y>，截止 <Z>。要建飞书任务吗？
```

> 模糊或一次派多个时，列点等他勾选，不要一股脑全建。

**Step 2：解析负责人**

用 [[lark-contact]] skill 把姓名换成 open_id。常见别名：

- 嘉欣 / 于嘉欣 → 于嘉欣
- 荔枝 / 何小琴 → 何小琴
- 娜娜 / 王娜 → 王娜
- 洪洪 / 洪丽华 → 洪丽华
- 庆弘 / 孙庆弘 → 孙庆弘

**Step 3：用 [[lark-task]] skill 建任务**

按 5.3 默认参数填，没写的字段先空着，建完报回执。

**Step 4：登记到看板**

同步追加一条到 [[03-公司/待办与跟进/团队任务看板]]，挂在对应人下面，注明来源（如「2026-05-13 祥书口述」）。

**Step 5：回报祥书**

格式：

```
✅ 已建飞书任务
- 标题：<title>
- 负责人：<name>
- 截止：<datetime 或"未设">
- 任务链接：<url>
- 本地看板：已记入 @<name>
```

### 5.5 不要做的事

- 不要替祥书做决定派给谁（关键词模糊时必须问）
- 不要漏挂【祥新任务】清单（漏挂等于飞了，团队找不到）
- 不要错挂成【祥新任务（祥书账号）】（那是祥书个人清单，不是团队清单）
- 不要回写状态（同事完成与否由他们自己点完成）
- 不要漏关注人=祥书（他要看见进度）
- 不要把祥书自己要做的事建给别人

### 5.6 与旧规则的边界

| 旧规则 | 现在的边界 |
|---|---|
| [[08-日报与团队任务规则]] 第四节：「AI 不要回写到飞书任务，只读」 | **本 SOP 5.4 起替代**：AI 可建新任务，但不更新已建任务的状态。看板仍只是祥书视角的汇总。 |
| `lark-xiangxin-yunying-task` skill | 保留，用于「同一件事派给运营组 5 人」批量场景。单点派任务用本 SOP。 |

## 六、AI 操作清单（每次接到新任务前自查）

- [ ] 任务是否属于现有 SOP 覆盖范围？是 → 走对应 SOP；否 → 看是否需要新建条目
- [ ] 是否涉及客户隐私 / 店铺后台数据？是 → 脱敏
- [ ] 是否需要写飞书任务？是 → 按第五节流程
- [ ] 是否需要写知识库？是 → 默认 `_待整理/` ；最终成品才进正式目录
- [ ] 是否需要同步飞书文档？是 → 按 4.2
- [ ] 完成后是否需要回报祥书？默认是，给链接 + 一句话总结
