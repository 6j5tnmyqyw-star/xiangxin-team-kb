# 询货库存台账 · 使用与维护 SOP

## 一、为什么建这个台账

客服收到客户询货后，没有统一的库存信息可查，只能逐一去问各供应商，效率低且经常无果。本周（询单服务台 5/4–5/10 分析）缺货类工单占总量 60% 以上。建立统一**询货库存台账**，让客服先查台账再问供应商，把反复被问、反复要等的货沉淀下来。

> 台账地址：https://xiangxingolf.feishu.cn/base/GDLRbt92UaYM8Ksb2RxcQpYOnaf
> （飞书多维表格「祥新·询货库存台账」）

## 二、客服怎么用（核心）

**第一步：先查台账。** 客户问"有没有 X / X 什么时候有货"时，先在台账按**品牌 / 品类 / 关键词**搜，看「能否供货」状态：

| 状态 | 含义 | 客服动作 |
|---|---|---|
| ✅ 有货 | 当前可供 | 按「供货来源」正常报价、下单 |
| ❌ 缺货 | 暂无货 | 据实告知客户，按需推荐替代款，**不要承诺到货时间** |
| ⏳ 需等待 | 有货期但要等 | 告知客户预计到货（见备注），问是否愿等 |
| ❓ 待确认 | 尚未核实 | 去问供应商，问到后**立刻回填**状态 |

**第二步：台账没有 / 状态是「待确认」→ 问供应商，问完回填。** 这是台账能长大的关键：每问到一款新的货，就在台账新增一行或更新状态，下次别人就不用再问。回填时填：货品名称、品牌、品类、规格/型号、能否供货、供货来源（哪个供应商）、最近确认日期（填当天）、状态更新人（填自己）。

## 三、采购怎么维护

- **每日同步有货状态**：主要供应商有货/缺货变化，及时更新对应行的「能否供货」+「最近确认日期」。
- 「需等待」的货到货后，改成「✅ 有货」并清掉等待说明。
- 长期缺货且无供货来源的货，备注标注，供选品参考。

## 四、AI 每日补充

每天 AI 从询单服务台筛出被反复问到的货 / 缺货款，作为「❓ 待确认」候选行写入台账，由客服或采购核实后转为正式状态。AI 不直接判定有货/缺货，只做"被问到了"的线索沉淀。

## 五、字段说明

| 字段 | 说明 |
|---|---|
| 货品名称 | 主列，能识别即可（如"哑光挖起杆 黑色"） |
| 品牌 / 品类 | 下拉选择，方便客服筛 |
| 规格/型号 | 码数、度数、杆身、颜色等关键参数 |
| 能否供货 | ✅有货 / ❌缺货 / ⏳需等待 / ❓待确认 |
| 供货来源 | 哪个供应商 / 吉客云 / 自有库存 |
| 最近确认日期 | 最后一次核实库存的日期，越新越可信 |
| 咨询次数 | 被客户问到的次数，反映热度，辅助选品 |
| 状态更新人 | 谁更新的，便于追溯 |
| 数据来源 | 询单服务台 / 客服手填 / 采购同步 |

## 六、红线

1. 「能否供货」状态以**最近确认日期**为准，超过一周未确认的视为待核实，报价前再问一次供应商。
2. 缺货款**不要向客户承诺到货时间**，除非「需等待」行的备注已写明确切货期。
3. 台账数据仅内部使用，不截图外传。
