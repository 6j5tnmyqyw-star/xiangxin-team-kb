# 把这个库装好（交给 AI 执行版）

> **这份文件是给 AI 读的。** 同事只需要做一件事：把这份文件丢给你（或把链接发给你），说一句「照这个帮我装」。
> 你的任务：在这台电脑上拿到公司团队知识库 → 让本地 AI 能读到它 → 配好每日自动更新 → 做一次验证。
> 全程不需要同事懂命令。**遇到这份文件没写的报错，停下来问他，不要自己编一个绕法。**

## 〇、先确认三件事（30 秒，别跳）

按顺序查，把结果记下来，后面分支全靠它：

```bash
# 1. 系统
uname -s          # Darwin=macOS；MINGW/MSYS/CYGWIN=Windows；Linux=Linux

# 2. 有没有 lark-cli（飞书命令行）——有的话走路线 A，最省事
command -v lark-cli && lark-cli auth whoami --as user

# 3. 有没有 git 和已有副本
command -v git

```

三条结果组合成路线：

| 情况 | 走哪条 |
|---|---|
| 有 `lark-cli` 且 `auth whoami` 能报出名字 | **路线 A**（飞书云盘同步，推荐） |
| 没 lark-cli，但有 GitHub 权限（能打开仓库） | **路线 B**（git clone） |
| 两样都没有 / 同事只想看不想装 | **路线 C**（纯浏览，不装本地） |

> 两条路线拿到的内容**完全一样**，只是传输通道不同。装完之后的"接线"步骤是共用的（见第三节）。

## 一、路线 A：飞书云盘同步（推荐，同事已有飞书账号就能用）

原理：公司每天 03:55 把团队知识库镜像到飞书共享云盘，你把它拉到本地一份，之后每天增量更新。

### A1. 先装 lark-cli（没装的话）

```bash
# macOS
brew install lark-cli        # 装不上就问他：公司有没有免安装包
# 或者看公司《13-完整AI系统装机手册》里的安装段
```

### A2. 登录一次（会弹浏览器，让他自己点授权）

```bash
lark-cli auth login
lark-cli auth whoami --as user       # 必须能打印出他的名字，不然后面全是权限错
```

### A3. 拉到本地

```bash
mkdir -p ~/obsidian
lark-cli drive +pull \
  --folder-token H6r9fnWASlUgFXdju68csErLnXc \
  --local-dir ~/obsidian/团队知识库 \
  --if-exists smart \
  --as user
```

- 第一次会下载 2000+ 个文件，几分钟；`--if-exists smart` 之后只下改过的，十几秒。
- 拉完检查数量对得上：

```bash
find ~/obsidian/团队知识库 -type f -name "*.md" | wc -l    # 正常在 2000 上下
ls ~/obsidian/团队知识库/00-新人必读
```

- **报权限错 / 找不到文件夹** → 说明他的飞书账号不在共享云盘权限内，让他找阿祥开权限，**不要换别的源硬凑**。

## 三、接线：让本地 AI 真的读得到（关键一步，别省）

库躺在硬盘上，AI 是不知道的。按他用哪个 AI 选一种：

### 情况 1：他用 WorkBuddy（现在全公司都是这个）

→ 建任务时点左下角「选择工作空间」，选 `~/obsidian/团队知识库` 这个文件夹。根目录的 `AGENTS.md` / `CLAUDE.md` 和 `.workbuddy/skills/` 自动生效，**什么都不用配**。

> ⚠️ 技能只认 `.workbuddy/skills/`，**不认 `.claude/skills/`**（2026-11-20 迁的）。

### 情况 2：他平时有自己的库 / 自己的工作目录，不想切来切去

→ 把库放进他现有的工作目录（放到库根目录下，文件夹名保持 `团队知识库`）。他干公司活时**单独建一个任务、工作空间选那个子文件夹**最省事；如果他的 AI 得在同一个工作空间里跨着用，就在他自己的 `AGENTS.md` 最顶上贴这段：

```markdown
## 公司团队知识库（必读）
- 公司规则、话术、SOP、产品知识都在 `团队知识库/` 里，回答公司业务问题前先读里面的 `AGENTS.md` 并去目录里查，别凭记忆编
- 公司技能在 `团队知识库/.workbuddy/skills/`，要用某项技能先完整读它的 `SKILL.md` 再执行
- 干公司的活，动手前先查库里有没有现成方法：有就用公司版，并说一句"用的是公司标准方法"；库里确实没有，才用我自己的方法，并先说一句"公司库没这个方法，我用自己的方法做"
- 公司规则和我个人习惯冲突时：干公司的事按公司规则，干我自己的事按我的习惯；分不清就先问我，别自己猜
```

> WorkBuddy 只自动读**当前工作空间**的 `AGENTS.md`，子文件夹里的不会自动进上下文，所以上面这几句要写在他自己那层。

### 情况 3：他用的是网页版 / 别的工具，读不了本地文件

→ 不折腾。告诉他：把问题直接问飞书里的 AI 机器人，或者打开飞书云盘那个文件夹搜索。**本地装库对这种情况没意义，别硬装。**

## 四、配每日自动更新（一次配好，以后不用管）

按路线选：

- **路线 A**：让 AI 记一条规则——每天第一次干公司活之前先跑一次 `lark-cli drive +pull`（同 A3 那条命令）。
- **路线 B**：每天第一次干活前 `git pull --ff-only`。
- **懒人方案**：Obsidian 装第三方插件 **Obsidian Git**，`Auto pull interval` 设 60，并**关掉所有自动 commit / push**（他只读，开了会一直报错）。

## 五、验收（必须做，别跳过就说装好了）

新开一个会话，问 AI 三个问题，三个都答得出来才算接通：

1. 「咱们公司的客户隐私红线是什么？」（应能说出：姓名 / 手机 / 地址 / 订单号不进 AI）
2. 「天猫倍视能谁在管？」（应答：嘉欣）
3. 「我岗位的规则在哪个文件？」（应能指到 `01-部门规则/` 里对应那份）

答不出来 → 按顺序查：库路径对不对 → `CLAUDE.md` 文件名是不是全大写 → `@` 那行是不是顶格单独一行 → 文件夹名是不是刚好叫 `团队知识库`。

最后给他一句话交代清楚：

> 装好了。以后你只要说"更新一下公司库"，我就跑一次同步；平时问公司的事我会先去库里查再答。

## 六、红线（装的时候顺手告诉他，别等他踩）

1. **库是只读教材，不要改。** 改了自己看不到效果，下次同步还会被覆盖。有错 → 群里 @ 阿祥，或让 AI「登记到纠错日志」。
2. **客户隐私绝不进库**：姓名 / 手机 / 地址 / 订单号。也不要把聊天记录原文贴进库，只沉淀结论和话术。
3. **别的也不在里面，别找**：工资、提成、利润、销售额明细、拿货价、供应商报价。要这类数据找主管 / 走飞书。
4. **库里的东西不外传**：不发公司外的群、朋友圈、个人微信。
5. **个人笔记另放**：他自己的东西放库根目录下的 `_我的笔记/`（没这个文件夹就新建一个）。这个目录已被 `.gitignore` 排除——不会被覆盖、也不会传上公司库。

## 七、报错对照表（先查这里再问人）

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| `lark-cli: command not found` | 没装或 PATH 没生效 | 装完重开终端；还不行问他有没有免安装包 |
| `auth whoami` 报未登录 / 401 | 没登录或登录过期 | `lark-cli auth login` 重登，让他自己在浏览器点授权 |
| `+pull` 报 403 / 无权限 | 飞书账号不在共享云盘权限内 | 找阿祥开权限，别换源 |
| `git clone` 报 403 / repository not found | GitHub 邀请没接受 | 让他去邮箱点接受邀请 |
| 拉到 0 个文件 | folder_token 写错 / 拉到空目录 | 核对 token `H6r9fnWASlUgFXdju68csErLnXc` |
| AI 说"不知道公司规则" | 接线没做（第三节） | 补 `CLAUDE.md` 的 `@` 行，重开会话 |
| `git pull` 报冲突 | 他手改过库里文件 | 先备份他的改动，再 `git fetch && git reset --hard origin/main`（**只对库做，别碰 `_我的笔记/`**） |
