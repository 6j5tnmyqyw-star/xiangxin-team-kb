# 库管·补货建议（replenish-advisor）

> 库存周报看"现在有多少、占了多少钱"；本 skill 进一步回答"**该补哪些、补多少、找谁拿**"。

## 一、什么时候用

- 「该补什么货 / 哪些要断货了 / 生成补货建议 / 补货清单 / 跑一下补货」
- 库存周报跑完后想接着出补货动作

**不适用**：
- 只想看库存现状/资金占用/滞销 → `jackyun-inventory-weekly`（库存周报）
- 单 SKU 实时库存/销量 → `jackyun-api`

## 二、前置：库存快照（每天定时自动产）

补货建议靠**多份快照的净出库**估算动销。快照来源 = 每日定时任务 `com.xiangshu.jackyun-inventory`（凌晨 3:20，browser-harness 连吉客云导出），归档到 `03-公司/财务数据/吉客云销售/库存快照/YYYY-MM-DD-仓库库存详情.xlsx`。
- ⚠️ 别再去 `99-附件/吉客云导出/`——那是早期手动导出的废目录，定时任务**不写**那里（2026-06-22 修正：advise.py 曾误读此处导致拿 7 天前旧数据）。
- 正常每天都有新快照；默认取最近 `MAX_SNAPS`（8）份估 μ/σ。要补导一份手动跑 `jackyun-inventory-weekly`。
- 间隔越规整越准（定时任务保证每天一份）。

## 四、报告分档（怎么读）— v2 围绕「再订货点 ROP」

头寸 = 可用库存 + 采购在途。

| 档 | 含义 | 动作 |
|---|---|---|
| 🔴 超卖急补 | 可用为负**且**仍在动销 | 立刻补，先补平超卖 |
| 🔴 紧急(破安全库存) | 头寸 < 安全库存 SS | 尽快下单，已无缓冲 |
| 🟡 到补货点(下单) | 头寸 ≤ 再订货点 ROP | **该下单了**（科学触发点） |
| 🟢 接近补货点(备货) | ROP ~ 1.3×ROP | 计划内备货观察 |
| ⚠️ 负库存待核 | 可用为负**但近期不动销** | **不是补货** → 对账/盘点问题，交库管核对 |

每行给「ABC / 日均 / 安全库存 / 补货点ROP / 建议补货 / EOQ / 预估占款 / 找谁拿」。

## 五、v2 算法与可调参数（科学版 2026-06-15）

对标库存管理标准方法，从「补到固定 30 天」升级成「ABC + 安全库存 + 再订货点」：

1. **动销 μ / 波动 σ**：用 `99-附件/吉客云导出/` **全部**快照的相邻净出库率序列估（不再只用两份）。σ 偏粗时按 `CV×μ` 兜底防低估缺货。「支撑天数」字段公司没维护（1% 非空），不用。
2. **ABC 分类**：按 动销吞吐价值(日均×成本) 累计 80%/95% 分 A/B/C。
3. **安全库存** `SS = z·σ·√L`，z 按 ABC 服务水平 **A 98% / B 90% / C 85%**。
4. **再订货点** `ROP = 日均·提前期L + SS`，提前期 L 按品牌配（独家如 Bushnell 14 天，多家可比价 7 天）。
5. **触发**：头寸 ≤ ROP 才补；**补到** ROP + 复盘周期(7天)需求。`EOQ=√(2DS/H)` 给经济批量参考。

**可调参数**（`advise.py` 顶部）：`SERVICE_Z` / `LEAD_TIME` / `CV_FLOOR` / `REVIEW_PERIOD` / `ORDER_COST` / `HOLDING_RATE`。

**⚠️ 已知局限**：提前期/订单成本是**配置估值不是实测**（舒怡给各供应商真实到货天数会更准）；快照少时 σ 偏粗。

## 六、升级路径（更准的动销）

当前用快照差估动销，窗口短、σ 粗。要更准：用 `jackyun-api` 拉近 30 天**真实销售订单**算日均销量 + 真实需求标准差 σ，替换「快照净出库」估算。届时单份快照（看可用库存）+ 真实销量序列就能算稳的 μ/σ，安全库存与 ROP 都更可信。
