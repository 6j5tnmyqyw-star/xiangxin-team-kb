# 建飞书任务（公司通用）

员工用自己账号建的每一条任务，都要落在【祥新任务】清单里，否则主管在清单里看不见、周会点不到、月底算不到。

## 铁律三条

1. **必挂清单**：【祥新任务】`a1b4297b-0a7a-4b0e-8748-e0b75ae15485`。每次建任务都带 `--tasklist-id`。
2. **建完读回**：拿返回的 `data.guid` 查一次，`tasklists` 为空就是没挂上，立刻补 `tasklist-task-add`，别跟人说"建好了"。
3. **别选错清单**：`a543155a-c25c-44f2-aa1e-c553b97697b4` 是「祥新任务（阿祥账号）」，阿祥私人用的，**不要往里放**。

## 建一条任务

```bash
lark-cli task +create \
  --as user \
  --summary "<任务标题：动词开头，说清做什么>" \
  --description "<做什么 / 交付什么 / 什么时候算完成>" \
  --assignee "ou_xxx" \
  --due "2026-MM-DDTHH:MM:00+08:00" \
  --tasklist-id "a1b4297b-0a7a-4b0e-8748-e0b75ae15485"
```

- `--assignee` 填**做这件事的人**的 open_id（不是自己的话，先跟对方或阿祥确认）。
- `--due` 必须带 `+08:00`，不留空；确实没截止就写当天 18:00。
- 描述里写清**交付物**：交什么文件 / 回什么结论，不要只写"处理一下"。

## 建完必须校验

```bash
lark-cli task tasks get --as user --task-guid "<刚返回的 guid>"
```

看两处：

| 检查 | 合格 |
|---|---|
| `tasklists` | 非空，且 guid 是 `a1b4297b-…` |
| `members` | 有 `role=assignee` 的人 |

`tasklists` 空了就补：

```bash
lark-cli task +tasklist-task-add --as user \
  --tasklist-id a1b4297b-0a7a-4b0e-8748-e0b75ae15485 \
  --task-id <guid>
```

## 建完怎么回话

跟委托人只说三句：**任务标题 / 派给谁 / 截止什么时候**，附一句「已挂【祥新任务】清单」。不要把整段 JSON 贴出来。

## 不要做的事

- 不要不挂清单就建（最常见，建完在任何人的清单里都找不到）。
- 不要挂到阿祥私人清单。
- 不要一次建一堆同标题任务（先 `lark-cli task +search` 查有没有重复的）。
- 不要替别人建任务再通知他——**先问，再建**；涉及钱、人、对外的，先问阿祥。
- 不要把客户姓名、手机号、订单号写进任务标题或描述。
- **不要批量 `+complete` 多人会签任务或带 `【下架】【调价】` 等标签的执行任务**（`+complete` 是整条任务结单，会一并清掉其他共担人的待办；批量清理超过 10 条须先列清单给阿祥确认）。
