# 纠错日志登记 / AI 提日报工作流（全员通用版 v1.2.0）

> 对应公司规则 005「错误登记流程」与 2026-07-08 日报口径：**纠错日志（有效问题提交）与工作日报二选一**，当天提交有效内容即计入日报考核。
> 发现问题后不用手动进飞书多维表格一格一格填——直接把情况（和截图文件）告诉你的 WorkBuddy，AI 一次填全、传附件、提醒触达处理人，形成标准闭环。

## Step 0：先分流（别什么都往表里塞）

- **❌ 紧急 / 当天要救火的事**（今天不处理就影响出单、发货、客诉、上下架）→ **不进表**，立刻去飞书群 `@对应人` 现场解决。
- **✅ 该进表（5 类典型问题）**：
  1. **订单物流**：发错货、揽收超时、单号异常、三方代发反复慢/漏发
  2. **客服售后**：客诉、退换/定制口径冲突、售后协作卡顿、聊天转接漏接
  3. **商品价格**：链接标错、价格倒挂/线上降价冲击线下、缺货未及时下架、库存差异
  4. **流程规则 / 跨部门协作**：SOP 缺失、交接断层、重复踩坑、对现有规则有修改建议（分类选「**规则建议修改**」，阿祥每周五专扫）
  5. **AI 工具 / 成本采购**：AI 错答、工具报错不好用、成本/报价/税点口径不清

## Step 1：收集信息（缺什么一次问完）

向同事确认以下 3 项（已有就不重复问）：

1. **发生了什么**（一句话标题）+ 具体背景 / 店铺 / 商品 / 影响
2. **截图附件**（强烈建议）：⚠️ 必须以**图片文件**形式拖进对话框或提供本地路径；**纯 Ctrl+V 粘贴进聊天框的图 AI 拿不到文件路径，传不上 Base**。
3. 🔴 **隐私红线**：截图和文字里若有**客户姓名、手机号、收货地址、订单号**，必须先裁掉或打码再登记。

## Step 2：一次填全写入【纠错日志 Base】

| 项 | 值 |
|---|---|
| Base 名称 | Claude纠错日志（全公司问题日志） |
| 链接 | https://xiangxingolf.feishu.cn/base/CWuIblgzqaW7lUsivCBccKSmnqf |
| `base_token` | `CWuIblgzqaW7lUsivCBccKSmnqf` |
| `table_id` | `tblfZ9iO2sqYEWTy` |

AI 根据问题情况自动判断并**一次性填全**以下字段（不要留空推回给阿祥补）：
- **分类**（9 选 1）：`订单物流` / `客服售后` / `商品价格` / `成本采购` / `内容创作` / `AI工具` / `团队管理` / `流程规则` / `规则建议修改`
- **优先级**：`高`（立即）/ `中`（本周）/ `低`（有空）
- **评分**：`1-10`（≥6 进入周五汇总候选）
- **期望交付时间**：`高`=当天 / `中`=本周末 / `低`=两周内（避开周末与法定节假日）
- **AI处理建议**：给出解题思路 / 建议承接人 / 规则化建议

```bash
LARK_CLI_NO_PROXY=1 lark-cli base +record-upsert \
  --base-token CWuIblgzqaW7lUsivCBccKSmnqf \
  --table-id tblfZ9iO2sqYEWTy \
  --as user \
  --json '{
    "错误问题场景": "<一句话标题>",
    "问题具体情况": "<背景/细节/店铺/影响（已去客户隐私）>",
    "分类": "<9选1>",
    "发现日期": "<今天 YYYY/MM/DD>",
    "发现人": [{"id": "<提交人本人 open_id>"}],
    "处理人": [{"id": "ou_xxx"}],
    "优先级": "中",
    "评分": 6,
    "期望交付时间": "<YYYY/MM/DD HH:mm>",
    "AI处理建议": "<解题思路/规则化建议>"
  }'
```

**避坑铁律**：
- 参数是 `--json` 不是 `--fields`；新建直接走 `+record-upsert`（没有 `+record-create`）。
- 不带 `record_id` 的 upsert **每次都新建、不去重**——同一条只跑一次，立刻从返回取 `.data.record.record_id_list[0]` 记下 `record_id`，绝不盲目重跑。
- 新记录索引有几秒延迟，刚写完搜不到不代表失败。
- **处理人怎么填**：明确该谁管就填谁（可多选）；拿不准就先留空，Step 4 告知阿祥定夺。**阿祥本人不填进「处理人」；已离职人员（洪洪、阿娟、邹国瑜）绝不填。**

## Step 4：主动通知处理人（只填表不算完成）

⚠️ **公司规则 003**：只填「处理人」字段容易被忽略。飞书评论 API 写不进多维表格，所以登记完后**提醒同事二选一触达**：
1. 在 Base 网页打开该条记录，在右侧评论区 `@处理人` 一句话写清「请做什么 / 期望何时反馈」（拿不准派谁就 `@阿祥`）；
2. 或直接建一条飞书任务（必须挂【祥新任务】清单 `a1b4297b-0a7a-4b0e-8748-e0b75ae15485`，附 Base 链接与期望交付时间）。

## Step 5：回报结果（验收凭据）

向同事返回：`record_id` + Base 链接 + 摘要（标题 / 分类 / 优先级 / 处理人 / 截图是否上传成功）；若优先级为「**高**」，明确提醒当天另行告知阿祥。

## 绝对不要做

- 不要勾「已入规则」（阿祥周五汇总后勾选）
- 不要拉全表「看看以前有没有」
- 不要把临时闲聊或紧急救火单塞进表
- **客户隐私（姓名 / 手机号 / 收货地址 / 订单号）绝不进表、绝不进截图**
