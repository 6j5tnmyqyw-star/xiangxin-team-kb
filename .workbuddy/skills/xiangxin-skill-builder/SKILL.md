# 非技术岗技能构建器（xiangxin-skill-builder）

> 把「每天/每周手工重复干的活」，变成**谁拿去都能稳稳跑通、不踩红线、不编数字**的公司标准技能。
> 详细采访清单见 `references/interview-playbook.md`，10 大防踩坑与数据防呆铁律见 `references/non-tech-guardrails.md`。

---

## 第一步：先看现成，再决定要不要采访

1. **先查重，绝不造重复轮子**：先扫现有技能目录（`.workbuddy/skills/` 或 `07-AI协作/skills/00-技能总索引.md`）。如果已有 80% 重合的技能，直接问用户：「已有 `XXX`，是在它上面补一条规则，还是另起一个？」
2. **如果刚才对话里已经跑过一遍这个活，严禁重新盘问！**
   - 直接从刚跑完的对话里提炼：**执行顺序 + 数据来源 + 用户纠正过的地方**（用户说「不对，50 块以下别管」「这个不能发大群」——这些纠偏才是最值钱的业务规则）。
   - 用一段短摘要给用户拍板确认，一轮过关。
3. **如果是全新需求，按「上次怎么做的」轻采访**：
   - 先让用户用自己的话讲一遍，再补问 **最多 3–5 个具体问题**（能给选项就不让写作文，绝不一次甩出 15 题问卷），详情按 `references/interview-playbook.md` 走：
     - ① 上次做这件事时，你第一个打开的是什么文件/系统？
     - ② 做到哪一步会停下来思考或拍板？
     - ③ 上次出岔子/返工是因为什么？
     - ④ 这件事最不能让 AI 擅自干什么？（红线）
     - ⑤ 做完怎么算「合格」？（定出 **3–6 条一眼能判对错的验收标准**）

---

## 第二步：把流程拆成三层 + 切出 v0 与 v1/v2

别把用户给的某一次具体例子写死进技能！逐项切清：

- **固定层**（写进技能步骤）：执行顺序、数据口径、输出格式、红线。
- **变化层**（做成输入参数/相对时间）：日期（定时任务一律写「昨天/上整月/最近7天」，**绝不写死某年某月**）、人名、店铺、具体文件。
- **判断层**（做成审批门禁）：用户说「这个得看情况」「超过 X 元我要过一眼」的地方。

同时把范围切干净：
- **v0（今天就跑通）**：只保最核心、最省时间的一步（比如先把「导出→清洗→出草稿」跑稳）。**如果一个任务其实包含 3–4 件事（如“自动化整个月底结账”），必须拆分，先做最耗时的那块。**
- **v1 / v2（写进演进路线，不丢也不硬塞）**：暂时缺接口/缺权限/需授权外发的能力，明确标清延后原因（① 平台做不到 / ② 缺凭证或接口 / ③ 留到下一版），给用户看得到路径。

---

## 第三步：装上 4 把安全锁（非技术岗技能必带）

写任何非技术岗技能时，下面 4 条必须默认装进去（详版见 `references/non-tech-guardrails.md`）：

1. **精准审批门禁（只卡 3–5 个关键口，不步步打扰）**：
   - 只卡：**外发（给客户/供应商/大群）、花钱/改价/下单、删改原数据、对外承诺**；读数据、算表、出草稿一路跑完不停顿。
   - 门禁必须亮明底牌（数量、对象、金额、发件身份），严禁问空洞的「准备好了要继续吗？」。
   - **凡是共享给同事使用的外发类技能，默认锁定为「仅出草稿（draft-only）」**，由本人确认后发出。
2. **零连接器兜底（必填）**：
   - 不能假设 API 或浏览器自动化永远不断。每个技能必须写清**无连接器时的手工兜底入口**（如「拖入吉客云导出的 xlsx / 粘贴群聊文字，照样出同款结果」）。
3. **数据完整性铁律（空值不是零 + 跨环节不串用口径）**：
   - **空值 ≠ 0**：分页截断（如吉客云 2000 行）不是全量；成本缺失/未跟踪不是毛利 100% 或零销量；活动日期为空不是「很新」而是「从未跟进」；日期晚于今天是脏数据；查无结果先反查筛选条件。
   - **跨环节不串口径**：公司全盘总额只能当背景参考，绝不能拿来当单渠道/单广告 ROI 的分母。
   - **没真建定时就不说「已设每周自动跑」**：没落到系统定时任务（launchd / T3 定时）时，如实说明并给提醒方案。
4. **客户隐私与岗位黑话红线**：
   - 客户真名/手机号/地址/订单号绝不进公共库、大群或 AI 公共提示词；
   - 技能全文用**祥新自己的大白话**（如「吉客云销售单」「三方发货群」「【祥新任务】清单」），不用抽象咨询黑话。

---

## 第四步：按标准目录落盘

```text
<skill-name>/               # 全小写 + 连字符，与 frontmatter name 完全一致
├── SKILL.md                # 核心流程，控制在 125–300 行（上限 500 行）
├── references/             # 细则、模板、踩坑库按需加载，不塞爆主文件
└── scripts/                # 重复性确定计算（算表/校验）封成脚本
```

**写 `description` 的秘诀（决定技能能不能被自动触发）**：
- 包含「做什么」+「什么时候用」，写进同事真正会说的大白话（如「对账」「核对挂账」「标红黄绿」），**略带进攻性防漏触发**，同时写一句「什么情况不触发」防误伤。
- 正文多写「**为什么要这么做**」，少堆全大写或满屏感叹号的死命令——模型懂了原因，遇到边缘情况才会灵活不跑偏。

---

## 第五步：拿已知正确答案实测对比（不验真不交付）

写完初稿后，立刻拿用户提供（或刚跑过）的 **1 个已知正确答案的真实案例**跑一遍，把技能输出和人工结果并排对照：
- 对得上 → 标为可用，把该案例存成回归基线；
- 多找或漏找了某条 → 直接问用户「这条你是故意跳过，还是该补进规则？」——**这一步问出来的，往往就是最核心的隐性规则。**

---

## 第六步：按祥新双库规范归位

- **阿祥自用/公司权威源**：落 `07-AI协作/skills/<name>/`，建软链到 `~/.workbuddy/skills/`、`~/.codex/skills/`、`~/.agents/skills/`、`~/.gemini/config/skills/`，登记 `07-AI协作/skills/00-技能总索引.md`。
- **给同事用（WorkBuddy）**：脱敏检查 0 隐私命中后，同步放进 `祥新团队知识库/.workbuddy/skills/<name>/`（⚠️ WorkBuddy 只认 `.workbuddy/skills/`，不读 `.workbuddy/skills/`）。
- **回写台账**：在 `07-AI协作/AI工作台账.md` 记一笔；如果是同事自己用 WorkBuddy 摸出的好技能，提醒走 `xiangxin-knowledge-feedback` 回传总库。
