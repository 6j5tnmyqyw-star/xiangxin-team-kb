# 需求采访手册（融合 launch-your-agent + build-agent）

> 原则：**像同行坐一起聊活，不像填行政审批表。** 3–5 个问题拿够信息就先出初稿，让用户改初稿比追着问 15 个问题快三倍。

## 一、采访节奏铁律

1. **刚做过就不重问**：如果本轮对话刚陪用户手工干完这件活，直接提炼「顺序 + 数据源 + 用户的每一次纠偏」，写成一屏确认清单问一句「按这个理解对不对？」。
2. **先让对方说完再塑形**：用户刚丢出一个想法时，先用 1 句开放追问（「展开说说，具体想让它干啥？你心目中跑通的第一版长啥样？」），等对方说完再给选项和拆分建议。
3. **能给选项不让写作文**：频率、数据源、输出格式、发给谁、v0 切哪块，尽量列 2–4 个具体选项让用户点选；每轮最多 1 个开放题。
4. **边界放到相关时再提**：别开场甩一屏免责声明。聊到要外发消息时再提「第一版建议仅出草稿」，聊到定时任务时再提「窗口要和频率对齐」。

---

## 二、5 个最高含金量问题（锚定“上一次真实操作”）

永远别问「你们平时一般怎么做的」（会得到空泛官话），改问**「带我走一遍你上次做这件事的过程」**：

1. **起点**：上次做这活，你第一个打开的文件 / 系统 / 群是啥？
2. **数据来源**：表里那个关键数字（成本/毛利/销量/名单）是从哪来的？
3. **判断点**：做到哪一步你会停下来自己想一想、或者去问老板？
4. **翻车点（最值钱）**：上次做砸了、或者被提醒返工，是卡在哪？
5. **禁区与验收**：绝对不能让 AI 自己干什么？做完后你看哪 **3–5 个点** 就能确认这次没毛病？

## 三、需求 → 技能要素映射表

| 采访聊清的点 | 落进技能的哪一块 |
|---|---|
| 叫什么、解决啥痛点、同事平时怎么喊它 | `name` + `description`（含触发大白话） |
| 哪几步固定、先后顺序 | `SKILL.md` 编号步骤 |
| 哪些数每次都变（日期/店名/人名/文件） | 输入参数 + 定时任务强制相对日期 |
| 哪几步要人工确认、红线是什么 | 审批门禁（带具体数量/对象/金额）+ 禁止事项 |
| 没接 API / 浏览器掉线怎么干 | 零连接器手工兜底路径（CSV/XLSX/粘贴文本） |
| 做完长啥样、3–6 条可勾选对错的标准 | 输出模板 + 验收标准（Outcome Rubric） |
| 以前有没有一份公认做对的成品 | 回归测试样本（先拿它验真再交付） |
| 以后想加但今天不急的（自动发送/多系统联动） | v1 / v2 演进清单（注明原因：缺权限 / 留待下版） |

## 四、锁稿前必做两项一致性自检

1. **频率 vs 回看窗口有没有打架**：
   - 例：每天跑一次，但回看窗口写「近 14 天」却没去重 → 每天 90% 都是重复旧信息！必须当场决定：缩短窗口、降低频率，还是加本地已处理去重表。
2. **定时提示词里有没有写死日期**：
   - 凡是每周/每月复用的技能，正文和示例里一律用相对日期（「昨天」「上周一至周日」「上整月」），严禁把「2026-11-18」这种具体日期写死进规则。
