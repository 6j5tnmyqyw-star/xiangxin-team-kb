# 非技术岗技能防呆与数据铁律（提炼自 Anthropic knowledge-work-plugins）

> 这些不是理论，而是中小公司在真实业务数据里最容易让 AI「一本正经算错账」的坑。写任何公司业务技能都默认继承本页规则。

---

## 一、数据防呆第一铁律：空值不是零（Absent ≠ Zero）

测试样本往往干干净净，真实业务表全是洞。**数据里的洞，如果不加提醒，AI 会默认把它当成「业务没事/数字为零」——这是最危险的错误方向。**

报出任何关键业务数字前，先反问一句：「**这个数字看起来这样，是因为业务真的如此，还是数据缺了一块？分不清就明说，别替老板猜。**」

| 常见真实坑（含祥新高频场景） | AI 容易犯的错 | 技能里必须写死的正确处理 |
|---|---|---|
| **导出被截断**（如吉客云图片列 2000 行上限、分页只拉前 10 条） | 把截断切片当成全盘总数 | 只能标为「局部样本」；总账必须来自全量源，或先关图片列重导 |
| **汇总行和明细行打架**（系统导出自带汇总块与下方明细不一致） | 直接抄顶部汇总数 | 永远以明细行重新求和核对，不一致时当场报异常 |
| **0 和空值混用**（成本未录导致毛利=100%、库存跟踪关闭导致销量=0） | 当成高毛利或零动销 | 明显反常的 0 / 100% 标「待核/缺失」，绝不拿进合计或排序 |
| **跟进日期为空**（客户从未被联系过，字段为空） | 日期筛选把它漏掉，以为“没有超期” | 空日期排在最久未跟进前面，单独标「从未跟进」 |
| **未来日期脏数据**（录错年份导致日期晚于今天） | 排序时被当成“最活跃客户”顶到第一 | 先和今天比对，晚于今天的日期一律按异常/空值剔除并告警 |
| **查无结果**（关键词/标签搜索返回 0 条） | 汇报“今天没有异常/没有询单” | 交叉核对总数/原文；空结果也是重大断言，须先排除查询条件错了 |
| **两个数据源差出一个量级** | 悄悄挑一个顺眼的用 | 把差异直接摆上台面，说明最终采用哪个口径以及原因 |

> 一句话底线：**指明「哪块缺数据」极有价值；编造一个假的「0」比沉默更害人。**

## 二、跨环节拼接三大暗坑（Chain Seams）

单个步骤都没错，错全出在「把上一步的数直接塞给下一步」：

1. **绝不拿大盘当小渠道的分母**：
   - 例：拿公司全月 300 万总营收，去除某一家天猫店万相台的广告费，算出来 ROI 高得离谱。
   - **铁律**：全盘总额可以带下去当「背景说明」，计算转化率 / ROI / 占比时，**分母只能是该动作真正能触达的那块盘子**，并同时把两个基数写清楚。
2. **没真建定时任务，绝不嘴上答应「已设为每周一自动跑」**：
   - 把“每周一次”写进 Markdown 文件里**不会让电脑周一自己醒过来**。
   - 只有在真实注册了定时调度（launchd / T3 定时）并确认下次触发时间后，才能说「已设好自动跑」；做不到就老实说「现在不会自动跑，我可以给你建个周期提醒或飞书日历块」。
3. **跨表时间基准要对齐**：
   - 销售表截止到昨天、库存快照是 3 天前、客户档案是 6 月的——混在一起算动销或周转天数必错。所有报告开头必须显式写清**每张底表的截止日期**。

## 三、写技能最容易翻车的 10 个毛病（避坑自检表）

1. **刚陪做完一遍还重新盘问** → 直接从对话提炼草稿让对方改。
2. **把上周二的例子写死** → 文件名、日期、人名、件数全部参数化。
3. **步步弹窗求审批** → 问 9 次还不如手工干；只卡外发、花钱、改价、删改 3–5 个真节点。
4. **审批问得太虚**（“准备好了发吗？”）→ 必须报清：发几条、发给谁、涉及多少钱、用谁的账号发。
5. **不拿真案例试跑就交差** → 没复现过一次已知正确答案，同事以后每次还是得全人工复核。
6. **满篇咨询/技术黑话** → 写成「吉客云」「三方发货群」「【祥新任务】」，用团队自己的词。
7. **把带外发的技能原样分享给同事** → 给别人用的一律先改「仅出草稿」，防止不了解隐含前提就发出去。
8. **重复造已有技能** → 动手前先查总索引，能补旧技能不建新技能。
9. **一个技能塞四件事** → 拆小！一个技能只稳稳打透一件事，先做最耗时的那块。
10. **没写零连接器兜底** → 写死“必须连浏览器/API”的技能，只要掉登录就全废；必须允许手动导表拖进来继续跑。

## 四、客户与公司隐私不外泄（与祥新红线对齐）

- **绝不出现在公共技能正文、团队共享库、飞书大群或通用提示词里的字段**：客户真实姓名、手机号、收货地址、完整订单号、员工薪资绩效、银行卡号、AppSecret / API Key。
- 需要用到客户明文数据的本地流程（如老客名单拆分）：只在本机受 `.gitignore` 保护的私密目录运行，且一人一表分开发本人，绝不上公盘。
