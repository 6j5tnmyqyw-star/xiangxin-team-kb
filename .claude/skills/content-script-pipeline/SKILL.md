# 短视频文案流水线

> **用途：** 把祥书脑子里的想法变成可拍的口播脚本。三段流程：搜话题定选题 → 采访写文案 → 整理归档。
> **前置必读：** 对应账号的工作流程文档——
> - 公司号（高尔夫）：[[04-内容创作/公司号/00-工作流程]] + [[04-内容创作/00-定位与方法论/公司号-定位]]
> - 个人号：[[04-内容创作/个人号-邹祥书/00-工作流程]] + [[04-内容创作/00-定位与方法论/个人号-定位]]
> - 两者共用：[[04-内容创作/00-定位与方法论/口播脚本结构]]（四段式）、[[07-AI协作/规则/03-内容创作规范]]（禁用词）

## 一、开场：先确认拍哪个号

祥书触发后，**第一句先问**：今天弄个人号还是公司号？（也可以两个都弄，那就先走完一个号的三段流程，再走另一个。）

确定后，读对应账号的 `00-工作流程.md` 和 `定位` 文档，把支柱配比记在心里：
- **公司号**：A 行业内幕 60% / B 客户故事 30% / C 基础科普 10%
- **个人号**：A 老板思考 50% / B 中年生活 30% / C 学习新知 20%

## 二、第一段 · 搜话题、定选题

目标：给祥书一批**够格的选题候选**，他挑出今天要写的。

### 2.1 四个口子捞素材（按优先级排）

> **优先级铁律**：录音里挖出的素材 > 已有选题库存量 > 素材库速记 > WebSearch 热点。录音是祥书亲口说的，最真实、最不容易撞车。

1. ⭐ **翻待开发库里的录音来源条目**（最高优先级）：对应账号 `01-选题库/待开发.md` 里，**带 `来源：[[录音原文/...]]` 标记的**——这些是录音 pipeline 漏过来的祥书亲口素材，候选清单**必须优先展示这一类**。
2. **翻待开发库其他存量**：同一份 `待开发.md` 里没标录音来源的，也算候选。
3. **扫 vault 素材库**：`04-内容创作/素材库/灵感速记.md`（重点看最近 7 天的）、`客户故事.md`、`工作小事.md`、近期日记 `01-每日/`
4. **WebSearch 搜热点**（最低优先级，主要给公司号）
   - 公司号：搜「高尔夫 装备 行业」「Bushnell / Garmin 新品」「高尔夫 新手 避坑」等，找能用「老板视角」切入的角度
   - 个人号：搜跟「老板/创业」「中年生活」「AI 应用」交叉的热点，但**只找引子，不做信息搬运**

> 如果待开发库里录音来源的条目不少于 5 条，可以**完全不跑 WebSearch**——纯真实素材出选题，质量更高。

### 2.2 产出候选，让祥书挑

给祥书 **5-8 条候选**，每条必须四栏填满（填不满的不算合格选题，不要硬塞）：
- **钩子一句话**（前 3 秒说什么，要让人停下来）
- **核心观点一句话**（整条视频就传达这一个点）
- **归属支柱**（A / B / C）
- **来源标签**：`【录音】` / `【素材库】` / `【WebSearch】` / `【存量】`——录音来源的排最前

候选列表直接发给祥书，让他选今天要写的（1-3 条）。**录音来源的候选必须排在最前面**，让祥书一眼就能看到"哪些是我自己说过的"。

### 2.3 选题入库

- 祥书选中的 → 写进对应账号 `01-选题库/待开发.md`（`### [A] 标题` 格式），然后**剪切到 `已选定.md`**
- 他扫了一眼觉得以后可能用的 → 留在 `待开发.md`
- 明确不要的 → 不入库，或进 `已废弃.md`

## 三、第二段 · 采访祥书、写文案

这是整个 skill 的核心。**好文案不是 AI 编出来的，是从祥书嘴里问出来的。**

### 3.1 采访规则

针对选中的选题，对祥书做结构化采访：

- **一次只问一个问题**，等他答完再问下一个，不要一口气抛一堆
- **往具体里挖**：要具体场景、具体对话、具体数字、具体的人（隐去身份）。
  - 反例："客户经常有售后问题" → 追问："最近哪一个客户？他具体说了什么？你当时怎么回的？"
- 按四段式的需要采集料：
  - **钩子**：有没有一个反常识的点、或一个具体画面能开场？
  - **铺事**：让观众进入语境的那个具体的事 / 对话是什么？
  - **拐点**：祥书区别于别人的那个独特观察——「但我后来才发现……」那一句是什么？
  - **落点**：想让观众带走的一句话
- 如果某一段他答得空，继续追问，**不要替他编**

### 3.2 写四段式初稿

料够了，按 [[04-内容创作/00-定位与方法论/口播脚本结构]] 写初稿：

1. 钩子（前 3 秒）：反常识或具体画面，禁止「今天我们来聊聊」式开场
2. 铺事：用采访里那个具体的事，具体 > 抽象
3. 拐点：祥书的独特观察，这段决定是「记录」还是「内容」
4. 落点：一句让人想截图/转发的话，不是说教

写作注意：
- **用祥书的口语**，不要书面腔、不要专业术语堆砌
- 个人号保住「真诚 / 不端着 / 想深一层」的味道；公司号保住「真实老板视角」
- 控制在 60-90 秒口播量（约 250-400 字）

初稿存到对应账号 `02-脚本/草稿/<标题>.md`，文件结构参考已有的 [[04-内容创作/公司号/02-脚本/待拍/不打高尔夫的老板]]：
标题 + `归属支柱` / `预估时长` + `## 脚本`（标 [钩子][铺事][拐点][落点]）+ `## 拍摄备注`。

### 3.3 祥书改，AI 配合

把初稿发给祥书，他改口语、改细节、改落点。AI 按他的反馈调，反复几轮直到他满意。

## 四、第三段 · 整理归档

祥书说文案 OK 了，做收尾整理：

1. **过禁用词**：对照 [[07-AI协作/规则/03-内容创作规范]] 的通用禁用词（极致、史上最低、第一、绝对、最、唯一、顶级、独家……）+ 测距仪类专属禁用词（军用级、百分百精准……），命中即改写后再给祥书确认一次。
2. **定稿归位**：脚本文件从 `02-脚本/草稿/` **移到 `02-脚本/待拍/`**。
3. **更新选题库**：这条选题已经写成脚本了，确认它在 `已选定.md` 里（已经从待开发剪过来了就不用动）。
4. **状态约定**：内容走到哪只看在哪个文件夹，脚本 frontmatter 不写「状态」字段。
5. **汇报祥书**：今天定了几条选题、写好几条脚本（给文件链接）、分别在什么阶段。

## 五、AI 介入边界

- AI 默认只写到 `待开发.md` 和 `02-脚本/草稿/`。
- **剪切到「已选定」「已废弃」、移到「待拍」「已发布」**——这些是状态推进决定，由祥书拍板，AI 在他确认后才动手。
- 采访环节绝不替祥书编故事/编观点，料不够就继续问或如实说「这段还空着」。

## 六、触发关键词

- 「搞选题 / 今天拍什么 / 搜点话题 / 有什么可以拍的」
- 「采访我 / 你问我 / 帮我把这个想法写成文案」
- 「写条文案 / 跑一下文案流程」
- 「帮我把文案整理一下 / 这条定稿了」

## 七、调度建议

- **公司号**：已配每日定时（见第九节），早上自动跑第一段、推飞书。
- **个人号**：暂手动触发。第二、三段（采访、整理）必须祥书本人参与，**不能无人值守**。

## 九、每日定时模式（公司号 + 个人号）

由 launchd 每天早上触发 `claude -p`，**无人值守只跑第一段**——采访和整理必须祥书参与，定时模式做到「出候选 + 创建飞书内参文档 + 推飞书消息」就停。

### 触发链路

| Job Label | 时间 | 账号 | sh |
|---|---|---|---|
| `com.xiangshu.content-daily-golf` | 每天 8:57 | 公司号 | `~/.claude/scripts/content-script-pipeline/daily-golf.sh` |
| `com.xiangshu.content-daily-personal` | 每天 9:30 | 个人号 | `~/.claude/scripts/content-script-pipeline/daily-personal.sh` |

> ⚠️ **脚本必须放纯英文路径**（`~/.claude/scripts/`），**不能**放 vault 里。中文 iCloud 路径在 launchd 下会 UTF-8 乱码导致 `can't open input file`（已踩过坑：日志里看到 `祥�\M--\M-^P AI` 就是这个）。

plist 文件已直接放在 `~/Library/LaunchAgents/`（不再走"从 vault 拷过去"流程）：
- `com.xiangshu.content-daily-golf.plist`
- `com.xiangshu.content-daily-personal.plist`

常用操作：
```bash
# 查状态
launchctl list | grep content-daily
# 重新加载（改完 plist 之后）
launchctl unload ~/Library/LaunchAgents/com.xiangshu.content-daily-golf.plist
launchctl load   ~/Library/LaunchAgents/com.xiangshu.content-daily-golf.plist
# 手动立即跑一次
launchctl start com.xiangshu.content-daily-golf
launchctl start com.xiangshu.content-daily-personal
# 看日志
tail -f ~/.claude/logs/content-daily-golf.log
tail -f ~/.claude/logs/content-daily-personal.log
```

### 定时模式做什么
`claude -p` 收到的指令是跑本节流程：
1. 按「二、第一段 2.1」**四个口子**捞素材，**录音来源优先**：
   - 公司号优先扫 `04-内容创作/公司号/01-选题库/待开发.md` 里带 `来源：[[录音原文/...]]` 标记的条目
   - 个人号优先扫 `04-内容创作/个人号-邹祥书/01-选题库/待开发.md` 里带 `来源：[[录音原文/...]]` 标记的条目
2. 产出 5-8 条候选选题（钩子/核心观点/支柱/来源标签四栏填满，录音来源排最前）
3. **写当天候选文件** `01-选题库/_每日候选/YYYY-MM-DD.md`（工作暂存）
4. **创建详细飞书文档**：用 lark-doc 建『YYYY-MM-DD {账号}选题内参』，含完整候选 + 每条录音原文片段 + 拍摄备注
5. **推送飞书消息**：用 `lark-push-xiangshu` 推简短摘要（编号+标题+一句话观点）+ 飞书文档链接，结尾提示「回复想写的编号」

### 祥书挑完之后
祥书在飞书回编号（经 lark-bot-daemon 进新会话，或他手动开会话）。处理时：
1. 读当天 `_每日候选/YYYY-MM-DD.md`
2. 选中的几条按 `### [A] 标题` 格式写进 `待开发.md` → 剪切到 `已选定.md`
3. 进第二段：采访祥书

### 候选文件清理
`_每日候选/` 是暂存区，挑完即可删当天文件；保留不超过 7 天，更早的清掉。

### 故障排查
- **退出码 127 / "can't open input file"**：sh 路径含中文 iCloud 路径，把脚本移回 `~/.claude/scripts/`
- **claude API 403 / 网络错误**：launchd 跑 `claude` 必须自己 `export HTTP(S)_PROXY`，sh 里已设默认 `127.0.0.1:7890`
- **飞书推送失败**：检查 lark-push-xiangshu skill 的 token 是否过期
- **没看到 next run 时间**：`launchctl print gui/$(id -u)/com.xiangshu.content-daily-golf` 看下一次触发；StartCalendarInterval 24h 内才会有 next
