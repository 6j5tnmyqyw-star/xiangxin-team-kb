# 祥新·师徒制教学（派学 + 台账 + 验收）

> **前置：** 先读 [`../lark-shared/SKILL.md`](../lark-shared/SKILL.md)。Base 命令细节按需读 [`../lark-base`](../lark-base/SKILL.md)，任务细节读 [`../lark-task`](../lark-task/SKILL.md)。

## 这套制度是什么（2026-05-25 祥书发起）

公司搞 **老带新师徒制**，本质是**教大家用 AI**。规则一句话：
> **师傅只带、只审、定标准；交付一律由徒弟完成，师傅不亲自上手。**

徒弟"学会了"要拿出**凭证**交付，师傅验收。交付方式**按类型自动定**：
- **操作类**（会用某个工具/skill）→ 交**截图**（操作过程+结果）
- **方法类**（学会一套打法/思路）→ 交**文档**（自己写步骤/心得，能教下一个人）

> 进阶：徒弟交付的截图/文档反过来能当下一批人的教材，让师徒制自己滚起来。

## 用法一：派学（最常用）

祥书说"给娜娜的徒弟嘉欣派个学会迎客客服副驾的任务"时：

```bash
cd "<本skill目录>"
python3 scripts/assign.py \
  --shifu 娜娜 --tudi 嘉欣 \
  --content "用迎客客服副驾起草一条询单回复" \
  --type 操作类 --days 3
```

脚本会一次做完：①建飞书任务（assignee=徒弟、follower=师傅、挂【祥新任务】、含交付标准）②台账写一条「待学」记录带任务链接。

参数：
- `--type 操作类|方法类` → 自动定交付方式（截图/文档）+ 写对应验收标准，**不用手填交付方式**
- `--days N` 期望几天内学会（默认 3，截止设为当天 18:00）
- `--note "..."` 备注；`--force` 跳过师徒树校验；`--dry-run` 只打印不真建

**先 `--dry-run` 看一眼再正式跑**，尤其批量派的时候。
人名认花名也认真名（嘉欣/于嘉欣都行），不认识的名字会报错——别瞎猜 open_id，先查花名册或补进脚本 `PEOPLE`。

## 用法二：验收（徒弟交付后）

徒弟在台账记录里上传了截图/文档（或飞书任务里交付），师傅验收时：

1. 找到台账记录的 `record_id`（按徒弟/学习内容搜）：
   ```bash
   lark-cli base +record-search --as user --base-token EZjsb727JaMQklshxFdcUzC7nNd \
     --table-id tblsKb81VpiyNHl3 --query "<徒弟名或学习内容>"
   ```
2. 验收通过 → 更新状态+验收结果：
   ```bash
   lark-cli base +record-upsert --as user --base-token EZjsb727JaMQklshxFdcUzC7nNd \
     --table-id tblsKb81VpiyNHl3 --record-id <record_id> \
     --json '{"状态":"已验收","验收结果":"通过：能独立完成"}'
   ```
   验收不通过 → `"状态":"打回重学"`，验收结果写清差在哪。
3. 飞书任务那边由徒弟/师傅自行点完成（任务与台账不强绑，台账是进度总览）。

## 一句话调用映射

- "给X的徒弟Y派个学会Z的任务/让X教Y学Z" → 用法一，判断 Z 是操作类还是方法类
- "验收/XX学会了/打回XX" → 用法二
- "看看师徒制进度/谁还没学" → 直接读台账 Base（按状态筛 待学/学习中）

## 边界

- 只管"教学任务的派发+台账+验收"，不替徒弟做事、不替师傅判断教得好不好。
- 交付凭证（截图/文档）是徒弟自己上传到台账或飞书任务，本 skill 不代传。
- 师徒树变动（加人/换带教）→ 改 `scripts/assign.py`；台账结构变 → 飞书 Base 里改。
