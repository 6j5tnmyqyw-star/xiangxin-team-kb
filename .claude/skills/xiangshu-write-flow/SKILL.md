# Xiangshu Write Flow：ChatGPT 外脑 + 真我整合 + 打磨

> **核心理念**：ChatGPT 给延展和资料密度，祥书给真实经历和独特观察，本 skill 把两边熔成一段「有 AI 没写过的细节、有别人没说过的视角」的口播稿。
> **不是**让 GPT 写稿——GPT 只是外脑/陪练。最终视角和情绪必须是祥书的。

---

## 一、流程总览（六步）

```
1. 接话题       (祥书一句话给我话题)
       ↓
2. 唤起 GPT     (browser-harness 开 Chrome → 打开 GPT 延展项目)
       ↓
3. 发起讨论     (把话题 prompt 进 GPT，拿到延展素材)
       ↓
4. 采集真我     (我追问祥书：你的真实经历/客户/数字/独特角度)
       ↓
5. 整合初稿     (GPT 素材 + 祥书想法 → 四段式初稿，允许适度扩写补饱满)
       ↓
6. 调用 humanizer-xiangshu 打磨 + 评分 + 落到草稿
```

每步细节见下文。

---

## 二、第一步 · 接话题

祥书触发后第一句先确认：

1. **哪个号？** 个人号 / 公司号（决定支柱配比 + 落地路径）
   - 个人号：A 老板思考 50% / B 中年生活 30% / C 学习新知 20%
   - 公司号：A 行业内幕 60% / B 客户故事 30% / C 基础科普 10%
2. **话题是什么？** 一句话说清楚（不用想完整，AI 帮延展）
3. **预期角度？** 如果他有初步想法，先记下；没有也行，GPT 出来后再聊

如果他直接给了完整话题，跳到第二步。

---

## 三、第二步 · 唤起 ChatGPT

### 3.1 加载配置

读取 `references/gpt-project-config.md`：
- 项目 URL
- 默认 prompt 模板（如果有）
- 注意事项（如祥书的项目里特殊的触发词/格式）

**首次运行无配置时**：
- 用 AskUserQuestion 请祥书提供：
  1. ChatGPT 项目的完整 URL（如 `https://chatgpt.com/g/g-xxx` 或 `https://chatgpt.com/?project=xxx`）
  2. 这个项目是干什么用的一句话描述
  3. 项目里有没有固定的提示词模板要先发
- 拿到后**立即写入** `references/gpt-project-config.md`，下次直接读

### 3.2 用 browser-harness 打开

按 [browser-harness](~/work/browser-harness/SKILL.md) 的标准用法：

```bash
browser-harness <<'PY'
ensure_real_tab()
new_tab("<GPT 项目 URL>")
wait_for_load()
capture_screenshot()
PY
```

**失败处理**：
- 如果 ChatGPT 跳到登录页 → 停下来告诉祥书"GPT 没登录，登一下我等"。**不要**自己输用户名密码
- 如果项目不存在/打不开 → 告诉祥书项目 URL 可能变了，让他重新提供

### 3.3 浏览器是祥书自己的 Chrome

browser-harness 连用户运行中的 Chrome，所以**祥书自己屏幕上能看到 GPT 界面**——这是 skill 设计的一部分：祥书边看 GPT 输出边给我反馈。

### 3.4 ⭐ 分屏布局（固定动作，每次都做）

打开 ChatGPT 后**必须**把 Chrome 移到屏幕**左半屏**——这样祥书左边看 GPT 输出，右边看 Claude Code 对话窗口（追问/汇报），两边同步进行。这是流程的硬性环节，不分屏不开始第三步。

**正确做法**：先用 browser-harness 读屏幕逻辑像素，再用 osascript 直接控制 Chrome 设置 bounds（**不能经过 Finder**，会触发 Apple Events 授权错误 -1743）：

```bash
# 第 1 步：拿屏幕逻辑像素宽高
browser-harness <<'PY'
info = js("return {sw: screen.width, sh: screen.height}")
print(info['sw'], info['sh'])  # 例：2560 1600
PY

# 第 2 步：osascript 直接调 Chrome（不要 tell Finder）
osascript <<'OSA'
tell application "Google Chrome"
    activate
    set bounds of front window to {0, 25, 1280, 1600}
end tell
OSA
```

`{0, 25, sw/2, sh}` = 从屏幕左上角下移 25px（避开 menubar），宽到屏幕一半。

**注意事项**：
- ⚠️ **不要 `tell application "Finder"`**——Claude Code 默认没有 Apple Events 给 Finder 的授权，会报 -1743；Chrome 自身的 Apple Events 通常已授权
- Chrome 在**全屏模式**（绿色按钮全屏）下 set bounds 无效，必须先退出全屏（按 esc 或 ctrl+cmd+f）
- 多屏环境下默认主屏，Chrome 不在主屏时需要先手动拖过去再跑脚本
- Stage Manager 开启时窗口位置可能被覆盖
- **Claude Code 对话窗口位置不归本 skill 管**，祥书自己摆右半屏（一般默认已经如此）
- 如要其他布局（左 6 右 4），改 `1280` 为 `sw * 0.6` 的实际整数即可

## 四、第三步 · 发起讨论拿素材

### 4.1 发 prompt

把话题以"延展请求"格式发给 GPT。基本模板（祥书的项目里可能有自己的模板，优先用他的）：

```
帮我延展这个话题：[祥书的话题]

我要做一条 60-90 秒口播。请给：
1. 这话题最反常识的 3 个点
2. 已经被人说烂的 3 个角度（我要避开）
3. 可能的具体场景/案例素材 5-8 个（数字、对话、人物都欢迎）
4. 一句话总结这话题最该传达的核心观点
```

通过 browser-harness 把 prompt 输入到 ChatGPT 输入框 + 点发送：

```bash
browser-harness <<'PY'
# 截图找输入框位置
capture_screenshot()
# 点输入框 + 输入 prompt + 发送
# (具体坐标根据截图决定)
PY
```

### 4.2 等 GPT 输出 + 抓内容

GPT 是流式输出，等到完整生成完（按钮从"停止"变回"发送"），抓全文：

```bash
browser-harness <<'PY'
# 等待生成完成（轮询"发送"按钮出现）
import time
for _ in range(60):
    if not js("return !!document.querySelector('button[aria-label=\"停止\"]')"):
        break
    time.sleep(1)
# 抓最新一条助手消息
content = js("""
const msgs = document.querySelectorAll('[data-message-author-role="assistant"]');
return msgs[msgs.length-1].innerText;
""")
print(content)
PY
```

把抓到的 GPT 输出**完整呈现给祥书**（虽然他屏幕上能看到，但我也要拿到，下一步整合要用）。

### 4.3 多轮追问（可选）

祥书看完 GPT 第一轮输出后，可能想让 GPT 再深挖某个角度。这时候：
- 祥书直接说"让 GPT 再写写第 2 点"
- 我把追问 prompt 输入 GPT，拿到新输出
- 直到祥书说"够了"

---

## 五、第四步 · 采集祥书真我（**最关键的一步**）

GPT 给的是公共知识/通用素材，没有祥书的独特性。这一步必须有，否则就是 AI 代写。

### 5.1 结构化追问（按四段式需要采料）

针对 GPT 的输出，对祥书做四个方向追问，**一次只问一个**，等他答完再问下一个：

**问 1 · 钩子料**：
> "GPT 列的这几个反常识点里，你最有共鸣的是哪个？你自己有没有一个具体场景能开场，或者一个反常识的数字？"

**问 2 · 铺事料**：
> "你身边有没有具体的人/客户/事，能贴上去做例子？最近发生的、还记得对话细节的。"

**问 3 · 拐点料**（重点）：
> "GPT 说的这些角度都挺常规的。你做这个 [行业/事] 这么久，你有什么是**别人不会这么想**的？或者你有没有从某件事里翻盘/打脸/想明白的瞬间？"
> 触发"但其实/我后来才发现/这件事真正让我想的是"这句的源头。

**问 4 · 落点料**：
> "如果观众只能带走一句话，你希望是什么？不用想金句，先说大白话。"

### 5.2 追问铁律

- **一次只问一个问题**，等回答再问下一个
- **往具体里挖**：他答"客户经常有售后问题"→ 追问"哪个客户？什么货？他原话怎么说的？你怎么回的？"
- **拐点段他答得空就再追问**：拐点是这条稿的灵魂，不能糊弄过去
- **不要替他编**：他答不出来就说"这段我先空着，看看要不要回到 GPT 再延展，或者你回头想到再补"

### 5.3 把真我料标记好

每段料标 `[钩子料]` `[铺事料]` `[拐点料]` `[落点料]`，跟 GPT 的素材分开放在自己脑子里——下一步整合时优先用真我料。

---

## 六、第五步 · 整合四段式初稿

### 6.1 整合规则（优先级）

写每一段时按这个优先级取料：
1. **祥书真我料**（首选，必须出现在每一段）
2. GPT 提供的素材里**祥书有共鸣的部分**（祥书选过的）
3. GPT 提供的素材里**通用知识的补充**（用来补饱满，但**不能挤掉真我料**）
4. 我可以适度填充连接句、对比、修辞（但**不能编故事/编数字/编客户**）

### 6.2 四段式结构

按 [口播脚本结构](../../04-内容创作/00-定位与方法论/口播脚本结构.md) 的四段式写：

- **钩子**（前 3 秒 / 1-2 句）：祥书真我料 + 钩子套路（见 humanizer-xiangshu §5）
- **铺事**（30-40% / 2-3 句）：用祥书的具体客户/事，GPT 提供的通用案例做补充
- **拐点**（30-40% / 2-3 句）："但其实/我后来才发现……"+ 祥书的独特观察
- **落点**（最后 1-2 句）：祥书的大白话料 → 我帮他打磨成对仗短句/反问/留白

### 6.3 字数控制
- 250-400 字（60-90 秒口播量）
- 超 450 字劝祥书拆两条

### 6.4 扩写边界

祥书说允许"稍微加一点点内容，让它饱满一点点"。**允许的扩写**：
- ✅ 补充 GPT 提供过的通用信息（数字、背景、对比）
- ✅ 写连接句（"问题就在这"、"你想想啊"）
- ✅ 写修辞（对仗、重叠）
- ✅ 把祥书的大白话润色成口播节奏

**禁止的扩写**：
- ⛔ 编造客户故事、编造对话、编造数字
- ⛔ 替祥书加他没说过的观点
- ⛔ 把通用观点说成是祥书的（"我觉得……" 但他没说过）

---

## 七、第六步 · 调用 humanizer-xiangshu 打磨 + 落地

### 7.1 切到 humanizer-xiangshu 流程

初稿写好后，**直接切到 [humanizer-xiangshu](../humanizer-xiangshu/SKILL.md) 的十步流程**：

1. 判段位
2. AI 痕迹扫描（必杀 13 条）
3. 真人特征保护（嘛/啊/咱们 别误删）
4. 钩子专项审（不到 7 分就给 2-3 个候选）
5. 拐点专项审
6. 落点专项审
7. 节奏体检
8. **事实与逻辑终审关（硬卡）**——核数字/型号/价格/承诺 + 逻辑自洽，存疑标 ⚠️待核请祥书确认，本关不过不能定稿
9. 五维打分
10. 输出（含 ⚠️待核清单）

### 7.2 输出格式

跟 humanizer-xiangshu §10 一致，固定这几块：
1. **改后稿**（按四段式标 [钩子][铺事][拐点][落点]）
2. **改动清单**（每条对应 humanizer-xiangshu 规则号）
3. **⚠️待核清单**（型号/数字/价格/承诺存疑项；有待核项时定稿前必须清空）
4. **五维评分**（钩子力 / 真我度 / 拐点锐 / 节奏感 / 落点钩，总分 50）
5. **钩子候选**（仅当钩子 <7 分）

### 7.3 落地

`02-脚本/草稿/<日期>-<标题>.md`，文件结构：

```markdown
---
日期: YYYY-MM-DD
账号: 个人号 / 公司号
归属支柱: A / B / C
预估时长: XX 秒
状态: 草稿
---

# 标题

## 口播稿
[钩子]
...
[铺事]
...
[拐点]
...
[落点]
...

## 拍摄要点
- ...

## 写稿来源
- ChatGPT 项目延展素材：（GPT 输出摘要）
- 祥书真我料：（采访摘要）
- 评分：钩子 X/10 · 真我 X/10 · 拐点 X/10 · 节奏 X/10 · 落点 X/10 = 总 XX/50
```

路径：
- 个人号 `04-内容创作/个人号-邹祥书/02-脚本/草稿/`
- 公司号 `04-内容创作/公司号/02-脚本/草稿/`

落地后**汇报祥书**：文件链接 + 评分一句话 + 是否要继续打磨 / 是否要进选题库。

| 你说 | 走哪个 skill |

| **"用 GPT 写 / 打开 GPT 写 X / GPT 协作"** | **本 skill** |
| **"我要写个 X 话题的稿"** | **本 skill**（默认走 GPT 协作） |
| "这条太 AI 了 / 加个钩子 / 润色一下" | humanizer-xiangshu（独立打磨） |

如果祥书在本 skill 流程进行中说"这段太 AI 了"，**直接走第六步 humanizer-xiangshu**，不要重启流程。

## 九、状态管理

本 skill 一次跑完一条稿，**无人值守不跑**（必须祥书在线参与第四步采访）。

中间任何一步祥书说"停一下"或"明天再继续"：
- 把已经拿到的 GPT 素材 + 真我料**存到** `_待整理/<日期>-<标题>-写稿中.md`（frontmatter 标"目标位置: 02-脚本/草稿/"）
- 下次祥书回来说"接着写 X"，从 _待整理/ 把它捞起来继续
