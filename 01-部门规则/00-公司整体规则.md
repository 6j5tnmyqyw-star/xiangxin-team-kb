## 【祥新公司规则 006】线上会议设备规范

- **生效日期**：2026-05-18
- **发布人**：邹祥书
- **适用范围**：全公司所有同事，凡参与公司线上会议（飞书会议 / 腾讯会议 / 其他平台）

**一、规则**

【会前 1 分钟自检】

1. **麦克风开关状态**：当前发言人开麦；其他人默认静音；切换发言时各自主动开/关，不依赖主持人提醒。
2. **设备距离**：麦克风离嘴一拳到一拳半（约 20-30 cm），太近会爆音，太远收音模糊。
3. **环境检查**：关掉外放音乐、电视、明显的风扇声；手机参会必须戴耳机，不要用外放（防回音）。

【会中执行】

4. **回音 / 噪音处理**：发现自己有回音、键盘声、背景人声，立即静音;主持人有权直接代为静音。
5. **听不清主动反馈**：听不清对方说话，直接在会议聊天框打字"X 听不清，请重说"或主动开麦提示,不要忍着开完。

**二、原因**

线上会议反复出现该静音没静音（回音 / 背景噪音）、该开麦没开麦（主讲讲半天发现没声音）、收音离太远听不清等问题，每次都要在会议里花时间打断纠正，浪费全员时间。基础设备问题不该反复在会议里强调。

**三、执行职责**

1. **所有参会人**：会前 1 分钟自检麦克风状态和设备距离，按规则切换开/关麦
2. **主持人 / 组织者**：开会前 30 秒提醒一句"请大家检查麦克风"；发现长时间噪音直接代为静音
3. **阿祥 / 主管**：抽查是否出现反复因麦克风问题打断会议，必要时纳入纠错日志

**四、违反处理**

同一场会议**两次**因麦克风状态错误打断会议，登记纠错日志（分类：团队管理）。

**五、来源 / 维护**

由阿祥发布与修订。

## 【祥新公司规则 005】错误登记流程

- **生效日期**：2026-05-15
- **发布人**：邹祥书
- **适用范围**：全公司同事，工作中发现"值得记录的问题"统一在此登记

**一、规则**
1. 登记入口：[Claude纠错日志 Base](https://xiangxingolf.feishu.cn/base/CWuIblgzqaW7lUsivCBccKSmnqf)。表名虽叫"Claude纠错日志"（历史命名），实际承载公司全量问题。
2. **必填字段**：错误场景（一句话）/ 分类（8 选 1）/ 发现日期 / 发现人 / 处理人 / 优先级。
3. **8 个分类**（单选）：订单物流 / 客服售后 / 商品价格 / 成本采购 / 内容创作 / AI工具 / 团队管理 / 流程规则。
4. **优先级**：高 = 立即处理 / 中 = 本周处理 / 低 = 有空再说。优先级"高"必须当天通知阿祥。
5. 登记后**必须在该条记录里评论 @ 处理人**（见公司规则 003），写清楚"请 TA 做什么 / 期望什么时候反馈"。只填字段不算完成登记。
6. 解决后由处理人填「正确做法」/「文本交付」/「附件交付」，并勾选「是否处理」。
7. 「已入规则」由阿祥周五汇总后勾选，他人不要勾。

**二、登记什么**

任何重复性 / 需约束 / 需交付的问题都登记：
- AI 错答（Claude / 小龙虾 给出错误输出或不符合团队铁律）
- 运营失误（价格、库存、订单、客服处理偏差）
- 流程漏洞（SOP 缺失、跨人交接、信息断层）
- 客户/售后反馈
- 团队/人事协作摩擦
- 内容/创作问题（违禁词、错误素材、视角问题）
- 供应链 / 成本 / 采购异常

**三、执行职责**

1. **发现人 / 登记人**：登记 + 评论 @ 处理人 / 跟进人，写明请求事项和期望反馈时间
2. **处理人**：处理完在评论里回复进度 + 填「正确做法 / 文本交付 / 附件交付」+ 勾「是否处理」
3. **阿祥**：定优先级（"高"必须当天介入派单）；周五汇总固化进规则

**四、违反处理**

- 登记不评论 @ 处理人：登记不算完成，阿祥发现后回退给登记人补 @
- 处理完不填「正确做法」直接勾「是否处理」：阿祥可撤回勾选，要求补齐

**五、来源 / 维护**

由阿祥发布与修订。AI 自动登记的完整工作流详见知识库 `07-AI协作/规则/11-问题记录与处理流程`。

## 【祥新公司规则 004】周会时间调整为周二 14:00

- **生效日期**：2026-05-19（自下周二起首次执行）
- **发布人**：邹祥书
- **适用范围**：公司各业务组的周例会（运营 / 销售客服 / 短视频 / 库房 / 财务 等）

**一、规则**
1. 自 2026-05-19 起，公司各业务组周例会**统一改为每周二 14:00 开始**。
2. 原各组周一 / 其他时段的周例会作废，按本规则执行（含原客服销售周会"周一 9:00-10:00"）。
3. 各组按自身议程定时长，单组原则上不超过 60 分钟。
4. 多组同日时段冲突时由阿祥协调先后顺序，避免撞车。
5. 会后 **2 小时内**由组负责人将周会纪要发至对应工作群，不得拖到次日。

**二、原因**

原各组周会分散在不同时段，跨组沟通节奏不齐，阿祥也不便参与所有组。统一到周二下午集中复盘，便于跨组听会、团队节奏对齐。

**三、执行职责**

1. **各组负责人**：组织本组周会，提前 1 天发议程，会后 2 小时发纪要
2. **阿祥**：跨组协调时段顺序，必要时调整起止时间
3. **全体参会人**：周二下午保留 14:00 起的会议时段，不另排冲突工作

**四、来源 / 维护**

由阿祥发布与修订。

## 【祥新公司规则 003】登记问题必须 @ 处理人 / 跟进人

- **生效日期**：2026-05-15
- **发布人**：邹祥书
- **适用范围**：全公司所有同事，凡是在「Claude 纠错日志」Base 登记问题

**一、规则**
1. 登记完一条问题，**必须**在该条记录里**评论 @ 处理人**，明确请 TA 跟进。
2. 如果除了处理人之外，还有希望同步知会 / 帮忙跟进的同事，**一起 @ 上**，不要事后再口头补。
3. 只填「处理人」字段、不评论 @ 不算完成登记——字段通知容易被忽略，@ 评论才会真触达。
4. 自己暂时不知道派给谁，可以 @ 阿祥让他定派单。
5. 评论里一句话写清楚"请 TA 做什么 / 期望什么时候反馈"，不要只丢一个 @。

**二、原因**

只填处理人字段，对方在飞书消息流里很容易划过去；登记的问题最后没人跟、堆在表里没人处理。评论 @ 是真触达，被 @ 的人飞书会直接红点提醒。

**三、执行职责**

1. **发现人 / 登记人**：登记完立刻评论 @ 处理人 + 跟进人，写明请求事项。
2. **处理人**：被 @ 后看到任务，按要求处理；处理完在同一条评论里回复进度，并勾选「是否处理」。
3. **阿祥**：被 @ 派单时定处理人，回评指派；周五汇总时检查是否所有记录都有 @ 评论。

**四、来源 / 维护**

由阿祥发布与修订。

## 【祥新公司规则 002】成本统一查吉客云

- **生效日期**：2026-05-14
- **发布人**：邹祥书
- **适用范围**：全公司所有需要查商品成本的同事

**一、规则**
1. 查商品成本统一去吉客云查，入口：**总仓库存查询**。
2. 只要是公司卖过的商品，成本在吉客云里都有，不用再问采购或财务。
3. 不以个人记忆、群聊旧记录、本地表格为准，一律以吉客云为准。

**二、原因**

成本来源不统一，各人报的数对不上。吉客云总仓库存查询是唯一权威成本源。

1. 改价指令下达后 ❓【待定·建议 2 小时】内必须完成，并回执"已改 ✅ + 截图"。
2. 跨店铺改价：每个店铺运营各自回执，**不得**"已转告"代替执行。
3. 控价类指令（不能跌破多少）须 ❓【待定·建议 30 分钟】内确认现价并回。

已发生案例：价格调整说了两天仍未执行，改价响应严重滞后。改价是抢流量、抢转化的关键动作，延误一天直接损失 GMV。
